# Migration Guide: GitHub Projects → Hula-Project Server

This guide helps you migrate from local GitHub Projects tracking to centralized hula-project server tracking.

---

## 🎯 Why Migrate?

**Before** (GitHub Projects):

- ❌ Complex OAuth setup with `project` scope
- ❌ Local polling drains resources
- ❌ No centralized tracking across team
- ❌ Data stored in local files
- ❌ Separate authentication for GitHub and tracking

**After** (Hula-Project):

- ✅ One-command authentication
- ✅ Server-side polling (zero local overhead)
- ✅ Centralized PostgreSQL database
- ✅ Team visibility (coming soon)
- ✅ Unified GitHub + tracking auth

---

## 🚀 Quick Start (New Users)

### Step 1: Install Hub-Launch

```bash
cd hub-launch
pnpm install
pnpm build
```

### Step 2: Authenticate

```bash
# One command to authenticate both GitHub and hula-project
GITHUB_APP_CLIENT_ID="Ov23lia19jei53m9q7yK" ./bin/hublaunch login --url http://localhost:3001

# Or if hula-project is in production:
GITHUB_APP_CLIENT_ID="Ov23lia19jei53m9q7yK" ./bin/hublaunch login --url https://hula-yourdomain.com
```

**What happens**:

1. Opens browser for GitHub authorization
2. Validates your GitHub account
3. Generates API key for hula-project
4. Configures `gh` CLI automatically
5. Saves credentials to config

### Step 3: Use Hub-Launch Normally

```bash
# Track an issue
./bin/hublaunch track microsoft/vscode#12345

# View tracked issues
./bin/hublaunch view

# Interactive mode
./bin/hublaunch

# All commands work exactly the same!
```

## 📦 Migration (Existing Users)

### If You're Using GitHub Projects

**Current config** (`.hublaunch/hublaunch.config.js`):

```javascript
export default {
  projectNumber: 123,
  projectId: 'PVT_kwDOABcD...',
  projectOwner: 'myorg',
  projectAutoSync: true,
  pollIntervalSeconds: 60,
};
```

**Step 1: Run Login**

```bash
GITHUB_APP_CLIENT_ID="Ov23lia19jei53m9q7yK" ./bin/hublaunch login
```

This adds to your config:

```javascript
export default {
  // New fields (automatically added by login command)
  hulaProjectUrl: 'http://localhost:3001',
  hulaApiKey: 'hula_sk_abc123...',

  // Old fields (deprecated, but kept for reference)
  projectNumber: 123, // Not used anymore
  projectId: 'PVT_kwDOABcD...', // Not used anymore
  // ...
};
```

**Step 2: Verify Remote Mode**

```bash
./bin/hublaunch view
```

You should see a message:

```
🔄 Using server-side polling (hula-project handles GitHub API)
```

**Step 3: (Optional) Clean Up Old Config**

Once you've verified everything works, remove old GitHub Projects fields:

```javascript
export default {
  hulaProjectUrl: 'http://localhost:3001',
  hulaApiKey: 'hula_sk_abc123...',

  // Remove these:
  // projectNumber: 123,
  // projectId: "PVT_kwDOABcD...",
  // projectOwner: "myorg",
  // projectAutoSync: true,
  // pollIntervalSeconds: 60,
};
```

## 🔧 Configuration Reference

### Required Fields (Remote Mode)

```javascript
export default {
  // Server URL (required for remote tracking)
  hulaProjectUrl: 'http://localhost:3001', // or production URL

  // API key (generated by `hula login`)
  hulaApiKey: 'hula_sk_...',
};
```

### Optional Fields

```javascript
export default {
  // Editor command (unchanged)
  editorCommand: 'code',

  // Plan storage (unchanged)
  planPath: '.hublaunch/plans',

  // Local tracking (fallback if hulaApiKey not set)
  trackingFile: '.hublaunch/trackedPlans.json',

  // Deprecated (GitHub Projects)
  // projectNumber: 123,
  // projectId: "PVT_...",
  // projectAutoSync: true,
};
```

## 🎨 Commands Reference

All commands work the same with remote tracking:

### Authentication

```bash
# Login (one-time setup)
hula login [--url <server-url>]
```

### Tracking

```bash
# Track a specific issue
hula track <owner/repo#number>

# Track your assigned issues interactively
hula track
```

### Viewing

```bash
# View all tracked issues
hula view

# Filter by status
hula view --status ready

# Filter by priority
hula view --priority High
```

### Interactive Mode

```bash
# Start interactive TUI
hula

# Server-side polling handles status updates
# No local GitHub API calls!
```

### Other Commands

```bash
hula watch <issue>      # Monitor PR and tests
hula close <issue>      # Close issue
hula checkout <issue>   # Checkout PR branch
hula merge <issue>      # Merge PR
hula priority <issue>   # Change priority
hula diff <issue>       # View PR diff
hula logs <issue>       # View workflow logs
hula respond <issue>    # Respond to Copilot
hula preview <issue>    # Preview deployment
```

## ❓ FAQ

### Q: What if hula-project server is down?

A: Hub-launch will show a clear error:

```
❌ Failed to connect to hula-project server
   Check that http://localhost:3001 is running
```

There's no fallback to local mode. The server must be available.

### Q: Can I use both local and remote tracking?

A: No. Hub-launch uses one adapter at a time:

1. If `hulaApiKey` is set → Remote (hula-project)
2. Else if `projectNumber` is set → GitHub Projects (deprecated)
3. Else → Local file

### Q: How do I switch back to local mode?

Remove `hulaApiKey` from your config:

```javascript
export default {
  // hulaApiKey: "hula_sk_...",  // Comment out or delete
  trackingFile: '.hublaunch/trackedPlans.json',
};
```

### Q: Where is my GitHub token stored?

Two places:

1. `~/.hublaunch/github-token` (for hub-launch)
2. `gh` CLI config (for `gh` command)

The hula-project server **never stores your token**.

### Q: How do I revoke access?

```bash
# Revoke GitHub App authorization
gh auth logout

# Delete local credentials
rm ~/.hublaunch/github-token

# Regenerate API key
hula login
```

### Q: Can I share my API key?

**No!** API keys are personal credentials. Each user should run `hula login` to get their own key.

### Q: How long is the API key valid?

Currently, API keys don't expire. You can set `expiresAt` in the database for expiration support.

## 🐛 Troubleshooting

### Error: "Failed to connect to hula-project server"

**Solution**: Check server is running:

```bash
curl http://localhost:3001/api/v1/plans
```

If not running:

```bash
cd hula-project
PORT=3001 pnpm dev
```

### Error: "Authentication failed: invalid API key"

**Solution**: Re-run login to generate new key:

```bash
hula login
```

### Error: "GitHub CLI not authenticated"

**Solution**: The login command should configure gh CLI automatically. If not:

```bash
gh auth login
```

### Issues not syncing from server

**Solution**: RemoteTrackingAdapter caches for 10 seconds. Force refresh:

```bash
# Exit and restart interactive mode
hula
```

Or wait 10 seconds for cache to expire.

## 🆘 Support

If you encounter issues:

1. Check server logs: `tail -f /tmp/hula-server.log`
2. Check hub-launch logs: Run with `DEBUG=*` environment variable
3. Verify configuration: `cat .hublaunch/hublaunch.config.js`
4. Check API key: Look for `hulaApiKey` in config
5. Test API directly: `curl -H "Authorization: Bearer hula_sk_..." http://localhost:3001/api/v1/plans`
